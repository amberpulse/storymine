# storymine

一个AI写作辅助工具，从真实的人类写的书里挖出**下一步该怎么办**。

> 很多人写作都会遇到一个问题：卡壳的时候“**接下来该如何发展剧情？**”，“**人物应该做出什么样的反应？**”。
> 人类作者已经用无数的本书和生动的描写回答过无数次。
> 这个SKILL就是把这些回答**存下来、找出来**，做成你专属的记忆库。

---

## 为什么不是直接“让AI自己想”

AI的建议经常没有逻辑、缺乏新意甚至不着边际：大模型的训练的是**统计平均**，会把“接下来该发生什么”抹平成一个平庸的“中位数”。

真正管用的是：“**某个作者在类似的剧情阶段，使用了什么方法来推进剧情。**”

所以这个SKILL不存剧情，只存**其他作者会怎么做**。

## 存什么，不存什么

| ✅ 入库 | ❌ 不入库 |
|---|---|
| 【露个破绽】——通过一件物品的物理重量反差，侧面暴露角色隐藏的非正常能力 | 主角看见室友单手拎起大箱子 |
| 【把人引上门】——借一个错位的地名信息，让陌生角色顺理成章切入主角生活 | 陌生人拿着写错地址的纸条找上门 |

**判断依据只有一条：换个故事还成不成立？**

- 成立 → 入库（它是可迁移的手法）
- 只对那本书成立 → 那是剧情复述，扔掉

## 一条记录长什么样

| 字段 | 说明 | 例 |
|---|---|---|
| `move` | 动作大类（12 类受控表） | 揭露 |
| `label` | 手法名（朴素直白，像句大白话） | 露个破绽 |
| `how` | 做法——**停在“手法”层，不含角色名、不含本书专有名词** | 通过一件物品的物理重量反差，侧面暴露角色隐藏的非正常能力 |
| `situation` | 什么样的局面下用得上（**检索键**，不作为展示内容） | 主角在不起眼的日常细节上察觉对方不对劲 |

外加元数据：出处（书/章）、原文片段（回溯用）。

**`move` 表**：引入 / 展开 / 升级 / 转场 / 反转 / 揭露 / 铺垫 / 放缓 / 悬置 / 收束 / 关系推进 / 立场转变

## 上手

### 依赖

**Python 3 + `curl`**。零第三方包。

### 配 API key

任何 **OpenAI 兼容**端点都能用。代码里不存任何凭据，给 key 只有两条路：

```bash
# ① 环境变量
export STORYMINE_API_KEY=sk-xxx
```

```jsonc
// ② 项目根放 config.json
{
  "api": {
    "base_url": "https://api.deepseek.com",
    "model": "deepseek-chat",
    "env_file": "~/.my_keys"        // 一个含 STORYMINE_API_KEY=xxx 的文件
  }
}
```

默认走 `https://api.deepseek.com` + `deepseek-chat`；换别的用 `config.json`，或命令行 `--base-url` / `--model`。

### 三步用起来

```bash
# ① 灌书（单个文件、或一整个目录都行）
python storymine.py extract 我的小说.txt --chapters 1-50

# ② 卡住了就问它 —— 直接说人话
python storymine.py query "我写到：主角刚认识一个可疑的人，两人要一起走一段路"

# ③ 看看库
python storymine.py stats
```

## 查询是怎么工作的

`query` **不是关键词匹配**——它把库里的条目塞进 prompt，让模型做**语义挑选**。

所以：

- 你**不用猜该搜哪个词**，直接描述你写到的处境就行
- 库大到一次塞不进时，会自动**分批扫全库 + 候选精选**（全库都看过，不漏书）

## 完整命令

```bash
python storymine.py extract <文件或目录> [--chapters 1-50] [--force]
python storymine.py extract <文件> --pattern "<章标题正则>"    # 自定义分章规则
python storymine.py extract <文件> --skip                     # 切分可疑时静默忽略

python storymine.py query "我写到……" [-n 5]                    # 卡住了问它
python storymine.py stats                                     # 库统计
python storymine.py list                                      # 浏览手法表
python storymine.py failures                                  # 还没解决的失败/可疑章

python storymine.py delete --book "书名"                       # 删除（默认只预览）
python storymine.py delete --book "书名" --chapters 30-35 --yes
python storymine.py delete --before "2026-10-15" --yes
```

**删除有三道闸**：默认只预览（要 `--yes` 才动手）、执行前自动备份到 `backups/`、删完对账。

## 几个设计取舍

**手法名不归集。** `label` 是自由命名的——同一招在不同书里可能叫「露个破绽」，也可能叫「露马脚」。**不修**，因为查询走的是语义匹配，名字统不统一**不影响查得到查不到**。归集只对"按名浏览/统计"有用，而它得人工逐条读——库一大就划不来。想归的人可以自己定一张表写进 `config.json` 的 `extract.vocab`。

**分章宁可粗、不可丢。** 切不出章标题的文件**不会跳过**，而是**整篇当一章**收下（片段、短篇、单章文件都能进）。切分可疑时会明确报警，并给两条路：`--pattern` 自定义规则重切，或 `--skip` 忽略。

**失败按类分流。**
- 瞬时的（坏 JSON、网络抖动）→ 自动重试，原命令重跑即可续
- 渠道内容审查拒 → **当场判死，不重试**（重试纯烧钱）
- 有章失败时 → **退出码非 0**，`failures` 能查出是哪几章

**退出码说真话。** `0` 全成功 / `1` 有失败 / `3` 撞配额墙。这是唯一不需要读输出就能收到的信号。

## 处理链

```
本地书（txt / md）
   ↓ 自适应分章（4 种标题格式 + 目录页清洗 + 重复标题合并）
章文本
   ↓ LLM 提取「叙事动作」（move / label / how / situation）
SQLite
   ↓ 检索（处境 → 手法）
"我写到 X → 别人这么处理过"
```

## 给 agent 用

如果你在用 agent（Hermes / DeepSeek Harness 之类），把仓库里的 **`SKILL.md`** 装进它的 skills 目录 ——
它就知道该怎么调这个工具了（包括"用户丢文件时先提炼再查""跑失败按类处理""不许写脚本绕过内核"这些规程）。

## 已知边界

- **不产出正文**——它给的是参考意见，不是文稿
- **只提取「叙事动作」一个要素**——大纲 / 人物 / 世界观不在范围内
- **不做自动爬书**——书得你自己准备好
